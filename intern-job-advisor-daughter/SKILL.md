## 核心分析流程

收到岗位信息后，依次执行以下六步：

### 第一步：岗位本质分类

先判断岗位真实定位，不要只看岗位名称：

| 类型     | 特征                       | 价值判断  |
| ------ | ------------------------ | ----- |
| 核心业务岗  | 直接对GMV/营收/用户增长负责，有独立决策空间 | 高含金量  |
| 成长型岗位  | 核心业务支持但能深度参与，有明确成长路径     | 有潜力   |
| 高含金量实习 | 能接触核心数据、核心流程、核心决策        | 简历加分项 |
| 校招跳板岗  | 大厂光环但职责偏执行，可通过平台跳槽       | 看情况   |
| 打杂岗    | 职责模糊，以"协助""支持"为主，无可迁移技能  | 不推荐   |

### 第二步：九维评估

对每个岗位输出：

| 维度              | 说明                               |
| --------------- | -------------------------------- |
| **岗位适配度（1-10）** | 综合专业匹配、方向契合、成长空间                 |
| **含金量**         | 高/中/低 — 这段实习写进简历值多少              |
| **是否值得投递**      | 是/否/看情况 + 一句理由                   |
| **是否能学到核心能力**   | 是/否 — 核心能力指运营方法论、数据思维、增长策略等可迁移技能 |
| **是否适合英语专业**    | 是/否/加分项 — 英语能力是硬门槛、加分项还是无关       |
| **是否适合女生长期发展**  | 是/否/看情况 — 考虑加班强度、晋升公平性、行业天花板     |
| **加班强度**        | 低/中/高/极高 — 基于公司文化和岗位性质判断         |
| **面试难度**        | 低/中/高 — 基于JD要求的技能深度              |
| **转正概率**        | 高/中/低/无 — 如果是实习转正岗               |

### 第三步：岗位方向归类

判断岗位更偏哪个方向（可多选）：

DTC / 平台电商 / 用户增长 / 市场营销 / 销售 / 内容 / 品牌

这决定了用户未来职业路径的走向，不同方向的成长天花板和薪资天花板差异很大。

### 第四步：关键词扫描

**高价值关键词**（出现时标注 **[核心亮点]** 并说明价值）：

- 用户增长 — 英语专业做增长有语言壁垒优势，竞争更小
- ROI / ROAS — 投放和运营的核心能力，最值钱的数据思维
- 转化率 — 核心业务指标，经验可迁移
- A/B Test — 增长黑客基本功
- CRM — 用户生命周期管理，高阶运营必备
- DTC — 直接触达消费者，行业最热方向
- 独立站 / Shopify — 品牌出海主阵地
- Meta广告 / Facebook Ads — 海外投放核心渠道
- TikTok Shop — 新兴渠道，红利期
- Amazon — 跨境电商基本盘
- 海外用户 — 英语专业天然优势区
- 品牌出海 — 完全契合用户目标方向
- 数据分析 — 虽非技术岗但需要基本数据sense，面试加分项

出现高价值关键词时提醒：**该岗位属于核心业务成长方向。**

**低价值关键词**（大量出现时标注 **[风险提示]** 并警告）：

- 协助、日常支持、整理资料、流程跟进、文档处理、行政事务、基础执行

大量出现低价值关键词时提醒：**该岗位可能成长有限，偏支持型。**

**注意**：如果岗位同时出现高价值和低价值关键词，看比例和主次。高价值为主则仍推荐，低价值为主则降级。

### 第五步：推荐等级与排序

按以下四档排序：

| 档位       | 含义                        |
| -------- | ------------------------- |
| **强烈推荐** | 适配度8+，方向完全匹配，核心业务岗，值得优先准备 |
| **推荐**   | 适配度6-7，方向匹配，成长型岗位，值得投递    |
| **保底**   | 适配度4-5，方向沾边，可投但不是首选       |
| **不建议**  | 适配度3以下，方向不匹配、打杂岗、成长有限     |

对每个岗位额外说明：

- 为什么推荐/不推荐
- 是否适合作为大厂跳板（平台光环是否值得）
- 对未来校招是否有帮助（简历含金量如何）

### 多岗位投递策略（对同一家公司投多个岗位时）

当用户同时投递一家公司的多个岗位时，在单岗位评估基础上额外分析：

| 维度 | 说明 |
|------|------|
| 命中率预判 | 哪些岗位最容易拿到面试（编制多/门槛低），哪些最可能被筛掉（编制少/竞争高） |
| 投递优先级 | 建议投递顺序和时间分配 |
| 筛选逻辑 | 为什么有的岗位会过、有的会挂——核心差异在**编制量 × 经验门槛 × 专业壁垒** |
| 入职后转岗空间 | 先入职门槛低的岗位，内部转岗壁垒通常低于外部重新投递 |

**核心原则**：对有强烈意愿的公司，采取"主攻+保底"策略——主攻最契合方向的岗位同时，另投1-2个命中率更高的同公司岗位作为实际入职切入点。**进来比什么都重要，内部转岗比外部重新投递容易得多。**

### 第六步：职业路径建议 + 面试建议

对适配度5以上的岗位，额外输出：

**职业路径分析**：

- 哪些岗位未来最赚钱（薪资天花板高）
- 哪些岗位成长最快（1-2年能独立负责业务）
- 哪些岗位最适合英语专业女生（语言壁垒+合理工作强度）
- 哪些岗位最接近"全球化品牌运营"（用户终极目标）
- 哪些岗位未来更容易进入字节/SHEIN/TEMU/安克/小红书/国际化品牌

**面试建议**：

- 面试高频问题（3-5个）
- 英文自我介绍优化建议
- HR看重点
- 如何包装用户现有经历
- 哪些经历最值得讲
- 是否需要补数据分析/运营知识
- 如何提高通过率

**入职策略（先易后难）**：

- 如果同一家公司投了多个岗位但只拿到部分面试，优先准备拿到面试的岗位，不要纠结没拿到面试的
- 先进去再转岗：内部转岗的难度远低于外部重新投递。先通过门槛低的岗位入职，熟悉公司业务和流程后，再申请内部调岗到更核心的方向
- 实习期的表现决定了转岗/转正的机会——入职后主动接触目标方向的团队/项目，展示能力比简历更有说服力

## 评分标准

适配度打分基于以下加减分：

**加分**：

- JD明确要求英语/双语 → +1
- 岗位涉及数据指标（ROI、转化率、GMV） → +1
- 公司在目标公司列表内 → +1
- 岗位属于第一优先级 → +2
- 岗位属于第二优先级 → +1
- 有海外市场/用户触达职责 → +1
- 提到平台运营（Shopify/Amazon/TikTok Shop） → +1
- 有独立决策空间、能owner项目 → +1

**减分**：

- 职责描述模糊，以"协助""配合"为主语 → -1
- 英语能力未被提及或仅锦上添花 → -1
- 偏纯翻译/纯行政/纯文员 → -2
- 与国际化业务完全无关 → -2
- 加班极重且非核心业务（纯消耗型加班） → -1

**面试难度**（结合JD要求 **+ 岗位稀缺度** 综合判断）：

- 低：JD要求宽泛，"专业不限"；岗位编制多、流动性大（如运营/媒介/销售支持）
- 中：要求1-2项专业技能（如"会基础数据分析"、"了解某平台"），需准备但不难；编制量中等
- 高：要求深度专业能力（如"有投放经验"、"会SQL"、"有独立站操盘经验"），需较长时间准备；**或JD要求看似中等但岗位编制极少、竞争激烈（如GTM/策略/管培生）**

> **注意**：GTM、策略岗、管培生类岗位即使JD只写"XX经验优先"，因其编制量极少（往往只招1-2人），实际竞争激烈程度为"高"。评估面试难度时不能只看JD字面要求，必须考虑岗位稀缺度。

## 分析原则

- 不要只看岗位名称，结合JD本质判断真实职责
- "大厂光环"不等于好岗位，拆开看每天实际做什么
- 关注可迁移技能的积累，而非短期品牌溢价
- 对英语专业来说，语言壁垒是护城河 — 能用上英语的岗位天然竞争更小
- 用户增长和DTC运营是当前行业最稀缺、薪资天花板最高的方向
- 实事求是，不吹不黑，打杂岗明确标注
- 面试难度 ≠ JD字面要求：同样写着"有经验优先"，GTM/策略/管培岗因为编制极少，实际竞争激烈程度远高于运营/媒介/销售支持等编制多的岗位。评估面试难度时必须结合岗位稀缺度判断
- 先入职再转岗是可行策略：对心仪公司，优先选择命中率高的岗位作为切入点，入职后再寻求内部调岗到更核心的方向

## 联网检索岗位

当用户没有提供具体岗位，或要求"帮我找合适的岗位"、"搜索当前在招岗位"时，执行联网搜索。

### 核心原则

**CDP 直达招聘官网是第一优先，WebSearch 不能替代 CDP 获取岗位数据。**

WebSearch 的局限性：搜索招聘信息时，WebSearch 返回的是招聘简章/新闻报道（如"安克创新有11大岗位族"），而非具体岗位名称和JD。真正的岗位数据只存在于公司招聘官网（飞书/自建站）。如果只依赖 WebSearch，结果就是"这家公司在招人"的泛泛信息，而非"有哪些具体岗位可投"。

因此流程调整为：

1. **先找官网**：WebSearch 搜索目标公司的招聘官网URL
2. **CDP 直达**：用浏览器打开官网，获取完整的在招岗位列表
3. **WebSearch 辅助**：仅用于薪资基准、公司背景、面试经验等信息补充

### 搜索策略

#### 第一步：寻找目标公司的招聘官网

用 WebSearch 搜索目标公司的招聘官网URL，关键词：`"[公司名] 校园招聘 官网"` 或 `"[公司名] career"`。

常见招聘官网类型：

| 类型 | 特征 | URL 模式 | 代表公司 |
|------|------|----------|----------|
| **飞书招聘** | 字节旗下ATS，SPA页面，岗位数据通过内部API加载 | `{公司}.jobs.feishu.cn/{tenant_id}/position/` | 安克创新（旧站）、蓝禾/图拉斯、影石Insta360 |
| **Mioffice招聘** | 飞书旗下另一ATS，与feishu同架构 | `{公司}.jobs.f.mioffice.cn` | 小米 |
| **Moka招聘** | 常见ATS | `{公司}.zhiye.com/campus` | SHEIN、OPPO、vivo、泡泡玛特 |
| **自建站** | 大厂自研招聘系统 | `career.{公司}.com`、`jobs.bytedance.com` | 字节跳动、华为、腾讯、大疆、安克创新（新站career.anker-in.com） |
| **聚合平台** | 实习僧/BOSS直聘 | `shixiseng.com`、`zhipin.com` | 日常实习信息 |

> **注意2**：部分公司同时运行两套招聘系统（如安克创新同时有飞书旧站和自建新站），CDP搜索时如发现一套系统中岗位有限，应尝试查找另一套系统。

**聚合平台API现状与接入策略：**

| 平台 | 官方API | 接入方式 | 风控等级 | Skill推荐策略 |
|------|---------|---------|---------|-------------|
| **实习僧** | ✅ 有（[开放平台](https://open.shixiseng.com/)） | RESTful API，MD5签名鉴权，需企业资质+IP白名单 | 低（500次/秒） | **第0层：API批量扫岗（零Token）** → CDP补充完整JD |
| **BOSS直聘** | ❌ 无公开API | 仅企业级ATS商业对接（Moka/北森等） | 极高（封号率~100%） | **仅用WebSearch `site:zhipin.com`** → 禁止CDP直达 |

**实习僧API技术细节（有企业资质时可用）：**
- 网关：`https://open.shixiseng.com`
- 鉴权：MD5签名 + `Authorization: Base64(app_id:timestamp)`
- 请求有效期：3分钟；频次：500次/秒
- 支持模式：无需用户授权（商户签名调用）/ 需用户授权（access_token）/ 一键登录
- **接入前提**：需提交企业资质并联系商务开通，配置IP白名单
- **零Token价值**：搜索阶段直接API批量获取岗位列表+基础信息，不消耗LLM额度，CDP仅用于获取完整JD

**BOSS直聘安全红线：**
- **禁止CDP浏览器直达BOSS直聘** — 风控极严，模拟操作封号率接近100%，且易触发设备指纹封禁和人脸验证

- 市面上Selenium/Puppeteer模拟点击或抓包逆向的"非官方API"均属非法，有法律诉讼风险

#### 第三步：从CDP获取的岗位列表中筛选适配岗位

在 CDP 打开的页面中，通过搜索框筛选关键词（如 `GTM` `海外` `运营` `市场` `营销` `品牌` `销售` `管培` `电商`），或手动浏览所有岗位标题，找出适合英语专业+出海方向的岗位。

**处理飞书/Mioffice招聘页面的注意事项：**
- 飞书/Mioffice页面是 SPA，分页点击可能不触发导航（React 内部状态控制）
- 如果页面有大量岗位（如安克24页240个），优先用页面内搜索框缩小范围
- 搜索无效时，记录可见页面的所有岗位名，标注"仅展示了前N页，建议去官网查看更多"

**搜索盲区补漏（关键词搜索作为分类筛选的兜底）：**
- 飞书/Mioffice 的 SPA 页面中，分类筛选（如"运营类"）可能不展示所有符合条件岗位——部分岗位可能因分类标签不一致被遗漏
- **兜底方案**：在用分类筛选查看后，必须在搜索框中输入核心关键词（如 `国际电商`、`GTM`、`海外`、`运营`、`市场`）进行独立搜索，观察是否有分类筛选未覆盖的岗位
- 如果搜索框对中文字符响应不稳定，尝试在 URL 后添加 `?keywords=国际电商` 参数直接导航（部分 SPA 支持）

**通过公司招聘公众号发现官方求职入口：**
- 部分公司（尤其是大厂）的官方招聘公众号会发布校园招聘网站的直达入口，这些入口 URL 可能不同于搜索引擎能搜到的通用官网
- 当某家公司的校招官网 URL 不确定时，可以在微信中搜索该公司招聘公众号（如"小米招聘""安克创新招聘"），从中获取最新官方校招网站的 URL
- 公众号中发布的校招入口通常含实习/校招专有路径（如 `xiaomi.jobs.f.mioffice.cn/internship`），比通用官网首页更精准

#### 第四步：获取完整JD（针对筛选出的岗位）

对筛选出的适配岗位，通过以下方式获取完整JD：
- CDP 点击岗位标题打开详情页
- 或者用 WebSearch 搜索 `"[公司名] [岗位名] JD"` 查看是否有第三方转载

#### 第五步：WebSearch 辅助信息（公司背景、薪资基准、面试经验）

在评估阶段，用 WebSearch 补充以下信息（此时才用 WebSearch）：
- `"[公司名] 薪资 福利 2026"` — 确认薪资基准
- `"[公司名] 面试 经验 [岗位方向]"` — 了解面试流程和难度
- `"[行业] [方向] 校招 薪资 2026"` — 行业薪酬参照

#### 第六步：校招季节感知（辅助判断）

不同月份的企业招聘重点不同，搜索时带入季节判断：

| 月份 | 招聘重点 | 搜索策略 |
|------|---------|----------|
| 3月-5月 | **春季校招** + 暑期实习 | 校招补录 + 暑期实习项目（如美的"美少年计划"） |
| 6月-8月 | **暑期实习** + 秋招提前批 | 暑期在岗实习 + 秋招提前批投递 |
| 9月-11月 | **秋季校招**（最大规模） | 所有公司开放最多岗位，重点搜索官网 |
| 12月-2月 | 日常实习 + 春招预热 | 日常实习为主，部分公司开放春招提前批 |

当前为 **5月下旬**，属于春季校招尾声+暑期实习集中开放期，搜索时优先关注"暑期实习""春招"标签的岗位。对于未在春招窗口的公司，注明"当前非招聘季，预计X月开放秋季招聘"。

### 搜索结果处理

1. 从**CDP获取的岗位列表**中提取具体岗位信息（公司、岗位名称、**发布时间**、**实习周期**、职责摘要、任职要求、投递链接）
2. 过滤掉明显不相关的结果（如技术开发类、纯职能类等不适合英语专业的岗位）
3. 对每个有效岗位按核心分析流程（六步）评估
4. 如果搜索结果中包含详细JD，直接评估；如果只有岗位名称和简短描述，标注"信息来自CDP浏览页面，建议查看完整JD"后给出初步评估
5. 优先展示目标公司列表中的岗位
6. **多重关键词去重与补漏**：同一个公司的岗位列表去重后，检查是否有命名方式不同但同样适配的岗位被遗漏（如"ANZ GTM实习生"和"欧洲GTM实习生"属于同一方向不同区域）
7. **历史结果比对**：如果有之前轮次的搜索记录，将本次结果与上一轮进行交叉比对，检查是否有上一轮已发现但本轮遗漏的岗位
8. **排序规则：** 最终结果按适配度从高到低排列，仅展示适配度 >5 的岗位。不剔除特定实习周期的岗位（无论实习周期长短均纳入），但需在摘要表格中明确标注每岗的实习周期供参考

### 输出格式

搜索完成后，在常规输出前增加一个搜索摘要。结果按**适配度从高到低排列**，筛选**适配度 >5** 的岗位。

```
## 岗位搜索结果

共筛选出 **X** 个适配度5以上的岗位：

| # | 岗位 | 公司 | 地点 | 发布时间 | 实习周期 | 适配度 |
|---|------|------|------|---------|---------|--------|
| 1 | ... | ... | ... | ... | ... | X/10 |

> **说明：** 按适配度从高到低排列。
---
（接下来按常规六步流程逐个评估）
```

### 搜索频率与质量保障

- 同一公司同一岗位不要重复搜索
- 如果用户要求"再搜搜"或"还有没有"，换不同的搜索关键词组合，重点覆盖之前未用过的关键词
- 每次搜索聚焦2-3个目标公司或岗位方向，避免搜索结果过散
- **质量检查清单（每次搜索完成后逐条确认）：**
  - [ ] 每家目标公司是否已通过 CDP 直达官网查看实际在招岗位？（WebSearch 不能替代）
  - [ ] 是否覆盖了"运营/管培/市场/销售/品牌/GTM"六种命名类别？
  - [ ] 是否与上一轮搜索交叉比对，没有遗漏之前已发现的岗位？
  - [ ] 是否去重了同一公司内方向相近的岗位？
  - [ ] 是否标注了每岗的实习周期？（防止筛选时遗漏可谈的岗位）

## 边界情况

- **信息不足**：JD过于简略时标注"信息不足，建议查看详细JD后再评估"，给出初步判断
- **岗位数量多**：超过10个岗位时，先按适配度快速排序输出排名，再逐个详细评估
- **非实习岗**：如果用户投的是全职校招，评估标准不变，额外说明晋升路径和长期价值
- **无法判断的公司**：不在目标公司列表中的公司，按业务方向和岗位职责正常评估，不加平台分
- **搜索结果为空**：某个搜索组合无结果时，换关键词重试一次；若仍无结果，告知用户该方向当前可能暂无在招岗位
