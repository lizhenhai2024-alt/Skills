针对大三英语专业、跨境电商/品牌出海/海外市场暑期实习申请场景的文件整理规则。

## Who Am I

湖南大学英语专业大三学生，GPA 3.53/4.00，CET4 578 / CET6 497 / TEM-4 Good。正在申请跨境电商/DTC/品牌出海/海外市场方向暑期实习，目标公司40+家（字节/TikTok、阿里国际、SHEIN、TEMU、Anker、大疆、小米、美的等）。

我的电脑根目录为 `D:\我的文件\`，所有整理以此为根。

## 文件识别规则

### 自动识别 → 归到 01_岗位投递

| 文件名特征 | 判断依据 | 目标 |
|-----------|---------|------|
| 含公司名+岗位 的 `.md` 文件 | 文件名匹配40+目标公司列表 | `01_岗位投递/公司名/` |
| 含"小红书检索"的 `.md` 文件 | 文件名→提取公司名 | `01_岗位投递/公司名/` |
| 含"实习岗位"的 `.md` 文件 | 文件名→提取公司名 | `01_岗位投递/公司名/` |
| 从招聘网站粘贴的岗位描述 `.md` | 内容含"岗位职责""任职要求" | `01_岗位投递/公司名/岗位JD.md` |

| **手机批量导入**：文件名含"IMG_""VID_""PANO_"等相机命名模式 | 手机默认命名 | `08_照片/99_手机导入/按YYYYMM分组/`（保留原始文件名） |

**截图二次处理规则**：
- 归入 `00_截图暂存/` 的截图，整理后提示用户确认是否需要移到 `01_求职相关/` 下对应公司文件夹
- 能识别出公司名的截图（文件名含目标公司名），直接归到 `01_求职相关/公司名/`
- 截图内容含"岗位职责""任职要求"的 → 提示用户是否归入 `01_岗位投递/公司名/岗位JD.md`

**证件照管理规则**：
- 命名格式：`证件类型_规格_底色_日期.jpg`（如 `一寸_白底_20260501.jpg`）
- 同规格多个版本 → 保留最新，旧版加 `_v1` 后缀
- 电子版原片（未裁切/未修图）→ `02_证件照/电子版_原片/`，加 `_原片` 后缀
- 提示用户哪些规格的证件照是求职常用（一寸白底、二寸蓝底），缺少的建议补充

**手机导入照片处理**：
- 从微信/QQ/手机导入的照片通常无有意义文件名，按修改日期 `YYYYMM` 分组
- 同一日期内按小时段分：`上午/下午/晚上`
- 如果能从EXIF提取地理位置信息，在目录名加地点：`202605_长沙_岳麓山/`
- **不重命名**手机导入的照片，保留原始文件名防丢失

**照片去重**：
- 相同尺寸+相同MD5 → 只保留一份，其余移入 `99_待整理/_重复照片_YYYYMMDD/`
- 文件名不同但内容相同的（如 `IMG_0001.jpg` 和 `微信图片_0001.jpg`）→ 保留文件名更长的，删重复
- 去重后输出报告：发现X组重复，保留Y张，清理Z张

## 协议

### 1. 预扫描

- 列出源目录内容（递归计数）
- 列出目标目录内容，检查**是否已有同名公司文件夹**——如果有，规划为合并而非覆盖
- 识别文件名中的中文字符、`&`、路径 >200 字符
- **特别检查**：目标公司文件夹中是否已有同名的岗位JD.md → 如果有，追加而非覆盖

### 2. 计划 & 分类

- 对每个文件执行文件识别规则（见上表）
- 能自动识别的 → 直接规划目标路径
- 不能自动识别的 → 标记为 `[需人工判断]`
- 生成 Markdown 计划表：`源路径 → 目标路径` 映射
- **先展示计划给用户看，等用户确认再执行**

### 3. 执行 & 验证

- 用 **Robocopy** 执行所有批量操作：`robocopy /E /MOVE /R:1 /W:1 /NFL /NDL /NP`
- **禁止使用 xcopy**（中文路径、`&` 字符会静默失败）
- 少于10个文件的小操作可用 PowerShell `Move-Item`
- 每次移动后验证：
  - 源文件已删除（移动）
  - 目标文件存在且文件大小一致
  - 没有文件意外落入 `99_待整理`
- **如果公司文件夹已存在**：Robocopy 默认合并，同名文件以较新的覆盖（检查修改时间）
- 验证失败 → 停止、诊断、调整方案、重试

### 4. 边界情况处理

- 中文路径 → 先用 Robocopy，失败则切 `[System.IO.File]::Move()`
- `&` 在路径中 → 确保 PowerShell 适当引用
- MAX_PATH (>260 字符) → 使用 `\\?\` 前缀或缩短目标路径
- 目标已有部分同名文件 → **检查修改时间**，保留较新的，旧版重命名为 `_v1` `_v2`

### 5. 特别规则：简历版本管理

这是最重要的规则。投不同公司会定制不同版本的简历：

- **主简历**：`02_简历求职信/主简历_李婧毓.docx` —— 通用版本，不做任何定制
- **公司版本**：`02_简历求职信/公司名_岗位名.docx` —— 针对该公司JD定制的版本
- **旧版本**：当更新简历时，旧版不删除，加 `_v1` `_v2` 后缀保留
- **从未整理文件夹整理时**：如果发现有多个"李婧毓_公司名.docx"散落各处，全部集中到 `02_简历求职信/`，去重后保留最新

### 6. 特别规则：投递状态跟踪

整理 `01_岗位投递/公司名/` 时，检查是否已有 `投递状态.md`：
- 没有 → 提示用户是否创建，模板如下：
  ```
  # 公司名 - 投递状态
  
  | 岗位 | 投递日期 | 状态 | 备注 |
  |------|---------|------|------|
  | TikTok策略运营(上海) | 2026-05-25 | 已投递 | 待回复 |
  | TikTok策略运营(深圳) | - | 待投递 | 需改简历 |
  ```
- 已有 → 不修改，仅提示用户确认是否需要更新状态

### 7. 特别规则：照片管理

**截图清理周期**：每次整理时检查 `08_照片/00_截图暂存/`，超过30天的截图提示用户确认是否删除或归档到对应公司文件夹。

**求职照片联动**：整理 `08_照片/01_求职相关/` 时，检查 `01_岗位投递/` 中是否有对应的公司文件夹。如果有面试通知截图但公司文件夹不存在 → 提示用户是否创建投递记录。

**证件照提醒**：如果 `02_证件照/` 中缺少以下任一规格 → 提示用户补充：
- 一寸白底（最常见简历照）
- 二寸蓝底（部分公司要求）
- 电子版原片（方便后续改规格）

**手机导入提醒**：处理完 `99_手机导入/` 后，提示用户 "有X张手机照片待分类，需要我按内容帮你分到对应的活动/生活目录吗？"
