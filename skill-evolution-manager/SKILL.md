# Skill Evolution Manager - 技能进化管理器

## 概述

**Skills的自我进化系统，让静态的Skill随使用经验持续成长。**

核心机制：通过外挂存档文件 `evolution.json`，记录对话中Skill的表现，自动迭代优化Skill，实现「一坑不踩两次」。

> **「这才是真正的自我进化，也可以理解为我们常说的复盘。」**

## 触发场景

当以下情况发生时自动激活：
1. 🎯 对话结束时（用户明确表示「结束」「完成」）
2. ❌ Skill执行出错、搞砸、未达预期
3. ✅ Skill表现出色、效果超预期
4. 💡 用户提出改进建议或反馈意见
5. 🔄 主动复盘：「总结一下这次skill哪里可以改进」
6. `/evolve` 命令
7. "复盘一下刚才的对话"
8. "把这个经验保存到 Skill 里"

## 核心设计理念

| 传统Skill | 进化型Skill |
|----------|------------|
| 静态不变，写完即定型 | 持续迭代，越用越好 |
| 错误重复犯 | 一坑不踩两次 |
| 依赖作者手动更新 | 从使用经验自动学习 |
| 所有人用同一个版本 | 个性化进化适配 |

**这个年代，持续的进化，才是唯一的真理。**

## 存档文件：evolution.json

**存储位置：** `~/.claude/skills/{skill-name}/evolution.json`

**数据结构：**

```json
{
  "skill_name": "skill-evolution-manager",
  "version": "1.2.0",
  "last_evolved": "2026-04-29T23:00:00+08:00",
  "evolution_history": [
    {
      "timestamp": "2026-04-29T23:00:00+08:00",
      "type": "bugfix",
      "description": "修复了表格输出对齐问题",
      "conversation_hint": "用户反馈表格乱码",
      "changes": ["修改了表格渲染逻辑", "添加了转义字符处理"]
    }
  ],
  "lessons_learned": [
    {
      "id": "L001",
      "scenario": "当Skill名称包含特殊字符时",
      "problem": "之前的正则无法正确匹配带横杠的skill名",
      "solution": "使用更宽松的匹配规则，允许-和_字符",
      "first_occurred": "2026-04-28",
      "fixed_in_version": "1.1.0"
    }
  ],
  "pending_improvements": [
    {
      "idea": "支持批量更新多个Skills",
      "priority": "medium",
      "suggested_by": "用户反馈",
      "noted_at": "2026-04-29"
    }
  ],
  "stats": {
    "total_evolutions": 5,
    "bugs_fixed": 3,
    "features_added": 2,
    "lessons_recorded": 8
  }
}
```

**字段说明：**
- `type`: bugfix（修复）、feature（新增功能）、optimization（优化）、clarification（澄清说明）
- `lessons_learned`: 踩过的坑、学到的经验，核心是「一坑不踩两次」
- `pending_improvements`: 待优化项，后续版本改进

## 工作流程

### 阶段1：对话中默默记笔记

**监控时机：** 对话进行中，Skill被调用时。

**记录内容：**
| 信号类型 | 记录触发条件 |
|---------|-------------|
| ❌ 错误 | Skill输出错误、逻辑不对、用户吐槽「这不对」 |
| ⚠️ 瑕疵 | 结果可用但体验不好，比如格式乱、速度慢 |
| ✅ 亮点 | 表现超出预期，用户说「这个好」「就这么做」 |
| 💡 建议 | 用户直接提改进意见「下次应该XXX」 |
| 🤔 困惑 | 用户反复追问说明表述不清，需要改进描述 |

**记录方式（临时内存）：**
```
临时笔记 = [
  { 时间点, 场景描述, 问题/亮点, 改进方向 },
  ...
]
```

**关键原则：**
> **「Skill哪里搞砸了、哪里需要改进，它全记在小本本上。」**

---

### 阶段2：对话结束，写入进化档案

**触发：** 用户说「结束」「完成」「就到这」，或对话自然终止。

**执行步骤：**

1. **整理临时笔记** → 去重、分类、提炼核心
2. **读取 evolution.json** → 没有则新建
3. **写入 lessons_learned** → 每条经验结构化记录
4. **更新 evolution_history** → 记录本次进化条目
5. **更新 stats 统计** → 进化次数+1
6. **保存文件** → 持久化存储

**脚本方式持久化：**
```bash
python {baseDir}/scripts/merge_evolution.py <skill_path> '<json_string>'
```
将经验增量写入目标 Skill 的 `evolution.json`。

**自动进化判断标准：**

| 笔记类型 | 是否自动进化 | 处理方式 |
|---------|-------------|----------|
| 明确bug | ✅ 是 | 直接修改SKILL.md修复 |
| 体验优化 | ⚠️ 待确认 | 写入pending_improvements |
| 新增功能 | ⚠️ 待确认 | 写入pending_improvements |
| 描述澄清 | ✅ 是 | 直接更新文档说明 |

---

### 阶段3：应用进化，更新Skill.md

**核心动作：** 将经验转化为Skill的实际改进。

**脚本方式缝合：**
```bash
python {baseDir}/scripts/smart_stitch.py <skill_path>
```
将 `evolution.json` 的内容转化为 Markdown 并追加到 `SKILL.md` 末尾。

**进化修改原则：**

| 修改类型 | 修改位置 | 示例 |
|---------|---------|------|
| 坑位规避 | 「常见问题」「注意事项」章节 | 添加：「注意：遇到X情况时，不要使用Y方法」 |
| 流程补全 | 「工作流程」「步骤」章节 | 插入缺失的中间步骤 |
| 边界处理 | 「异常处理」「边缘情况」 | 新增边界条件的处理方案 |
| 示例补充 | 「使用示例」章节 | 添加新的正反例对比 |
| 描述优化 | 「概述」「触发场景」 | 改写模糊不清的表述 |

**进化修改格式要求：**
每次自动修改后，在文件末尾追加：

```markdown
---

## 进化记录 v{版本号}

**进化时间：** {时间}
**进化来源：** {对话场景简述}
**本次变更：**
- {变更1}
- {变更2}

**学到的教训：**
> {核心经验总结}
```

## 使用示例

### 示例1：记录一次失败教训
**对话场景：**
> 用户：「你这个skill生成的表格怎么全乱码了？」
> 
> Claude：「抱歉，是特殊字符处理的问题，我修复一下。」

**进化管理器自动记录：**
```json
{
  "id": "L001",
  "scenario": "生成包含特殊字符的Markdown表格时",
  "problem": "未对 | * _ 等字符转义，导致表格渲染混乱",
  "solution": "输出前对特殊字符进行转义处理",
  "first_occurred": "2026-04-29",
  "fixed_in_version": "1.0.1"
}
```

**自动更新Skill.md：**
在「注意事项」中新增：
> ⚠️ **转义提醒：** 输出表格前必须对内容中的 `|`、`*`、`_` 等Markdown特殊字符进行转义，避免渲染混乱。

| 等级 | 进化次数 | 称号 | 特征 |
|-----|---------|------|------|
| Lv.1 | 0 | 初生 | 初始版本，未经实战 |
| Lv.2 | 1-3 | 见习 | 踩过几个小坑 |
| Lv.3 | 4-10 | 成熟 | 大部分常见坑已规避 |
| Lv.4 | 11-20 | 老练 | 有丰富的实战经验 |
| Lv.5 | 21+ | 宗师 | 经历大量迭代，近乎完美 |

## 注意事项

### 跨版本对齐（skill-manager 更新后）
当 `skill-manager` 更新了某个 Skill 后，应主动运行 `smart_stitch.py`，将之前保存的经验"重新缝合"到新版文档中。
```bash
python {baseDir}/scripts/align_all.py
```
一键遍历所有 Skill 文件夹，将存在的 `evolution.json` 经验重新缝合回对应的 `SKILL.md`。常用于批量更新后的经验还原。

### 核心脚本

| 脚本 | 用途 |
|------|------|
| `scripts/merge_evolution.py` | 增量合并工具。读取旧 JSON，去重合并新 List，保存 |
| `scripts/smart_stitch.py` | 文档生成工具。读取 JSON，在 `SKILL.md` 末尾生成或更新最佳实践章节 |
| `scripts/align_all.py` | 全量对齐工具。一键遍历所有 Skill，重新缝合经验回 SKILL.md |

### ✅ 应该进化的情况
- 明确的bug和错误
- 用户反复遇到的困惑点
- 多次出现的相同问题
- 流程中缺失的关键步骤

### ⚠️ 谨慎进化的情况
- 用户个人偏好（而非普遍问题）
- 临时场景的特殊处理
- 争议性的改动
- 涉及核心逻辑的大改

### ❌ 禁止自动进化的情况
- 没有明确证据的「可能改进」
- 用户只是随口一提的想法
- 未经证实的假设
- 破坏原有核心功能的改动

---

## 最佳实践

- **不要直接修改 SKILL.md 的正文**：除非是明显的拼写错误。所有的经验修正应通过 `evolution.json` 通道进行，这样可以保证在 Skill 升级时经验不丢失
- **多 Skill 协同**：如果一次对话涉及多个 Skill，请依次为每个 Skill 执行上述流程

## 设计哲学

> **「我们的Skills，终于就不再是一个静态的东西，而是随着我们的使用、我们的迭代，也跟随着我们一起升级了。」**

这个Skill的本质是：**把对话中的经验转化为可复用的知识。**

- 每一次失败，都让Skill更强
- 每一次反馈，都让Skill更懂你
- 每一次对话，都是一次训练
- 用得越多，进化得越好

**这就是持续进化的力量。**
