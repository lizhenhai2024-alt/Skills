# 合并处理器

用于处理补充材料、新实施例、新章节、扩展内容等增量场景。

## 执行门禁（优先执行，不可跳过）

1. 读取当前最新版交底书 MD 文件（如有多个，取时间戳最新的）
2. 读取用户提供的新材料/新内容
3. 识别新材料中与现有交底书的**重叠**和**新增**部分
4. 不覆盖旧稿，输出新文件

## 合并策略

### 重叠部分
- 如果新材料对同一描述给出了更精准的信息，**以新材料为准**，并在对话记录中标注替换依据
- 如果新材料与现有内容不一致，标记 `[注：与旧版矛盾，已采用新版]`
- 如果新材料只是对已有内容的另一种表述，保留原有清晰表述，不强行替换

### 新增部分
- 合并到对应章节位置
- 如果是新实施例（如第二实施例），加在 §6 具体实施方式下，格式：`实施例2：[名称]`
- 如果是新附图，追加编号并同步更新附图清单

### 不合并
以下类型不在本次合并范围内：
- 新材料提出了**独立的新技术问题** → 建议单独出案或新案件
- 新材料属于**不同保护对象** → 建议拆案

## 合并后动作

1. 另存为 `{案件名}_{YYYYMMDDHHmmss}.md` + `.docx`
2. 追加到 `交底书修订对话记录.md`：
```
[时间戳] 合并操作
- 合并内容: [摘要]
- 冲突处理: [N处，列出]
- 新增章节: [列表]
- 输出文件: {文件名}
```
3. 在对话中输出**合并摘要**（不超过 10 行）：

```
合并摘要
════════
操作时间: [timestamp]
合并来源: [文件/描述]
新增内容: [条目列表]
冲突与替换: [冲突数量] 处
受影响的章节: [列表]
输出: {文件名}.md / .docx
════════
```
4. 对新稿执行 Step 8 自检 `disclosure_self_check.md`
