# 中文专利交底书主模板

## 0. 项目信息

- 项目代号：
- 发明名称（当前推荐）：
- 备选名称 1：
- 备选名称 2：
- 发明人：
- 申请主体：
- 目标专利类型：
- 建议保护层级：零部件 / 总成 / 系统 / 方法
- 是否建议双轨：仅发明 / 仅实用新型 / 发明+实用新型
- 是否存在拆案建议：
- 前置筛查结论：
- 前置筛查日期：

名称优先按以下思路拟定：

1. 零部件类：`XX件和减振器`、`XX总成和减振器`
2. 总成类：`XX总成和减振器`
3. 系统类：`XX总成、主动减振器和减振器油路系统`
4. 方法类：`XX方法、系统和相关设备`

如缺少前置筛查报告，写明：

`前置筛查状态：尚未提供专利检索/FTO 初筛结果，以下交底内容不代表已完成现有技术或侵权风险判断。`

## 1. 所属技术领域

用一小段写清楚所属技术领域，优先写具体子系统，不要只写大类。

## 2. 背景技术

优先按四步写：

1. 先说明该零部件、总成或系统在整机中的作用
2. 再说明当前常见结构、最接近方案或参考专利
3. 接着指出 1-2 个具体工程缺陷，不要只写空泛性能不足
4. 最后自然引出本案要解决的技术问题

可直接套用的句式：

- `现有的 XX 结构通常采用……`
- `在 XX 工况下，容易出现……`
- `现有方案虽然能够……，但仍存在……`
- `因此，如何实现……并避免……，是本领域需要解决的技术问题。`

## 3. 发明要解决的技术问题

用一段话明确矛盾或缺口，优先写成“场景 + 缺陷 + 后果 + 目标”的形式，例如：

- 舒适性与操控性
- 消泡效果与装配负荷
- 响应速度与稳定性
- 成本与耐久性

推荐句式：

`现有方案在 A 场景下存在 B 缺陷，导致 C 后果，因此需要一种能够实现 D 并避免 E 的方案。`

## 4. 技术方案

### 4.1 整体结构或整体流程

只列与新颖性、创造性或权利要求支撑有关的部分。

如果当前方案同时包含多个彼此独立的技术路径，在本节先标出：

- 哪条路径是主案
- 哪条路径更适合作为备选拆案
- 哪些内容只是实施例支撑，不建议单独成案

### 4.2 关键创新点

每个创新点至少写清：

- 名称
- 位置与连接关系
- 关键结构或控制特征
- 作用机理
- 对应技术效果

### 4.3 控制逻辑或工艺路径

仅在方案确实涉及控制策略、制造工艺或流程时展开。

## 5. 有益效果

按“结构/逻辑变化 -> 机理 -> 效果”来写。

优先用以下表述：

- 通过……
- 从而……
- 有助于……
- 可降低……
- 预期减少……

没有实测数据时，不要写成已验证事实，也避免直接写“显著提升”“大幅优化”之类结论性措辞。

## 6. 具体实施方式

至少给出 1 个实施例。尽量覆盖：

- 应用场景
- 关键尺寸或参数窗口
- 材料或工艺说明
- 工作过程
- 与普通方案相比的差异点

## 7. 附图清单与附图说明

至少列出：

- 总体结构图
- 关键局部结构图
- 流程图或控制图（如相关）

## 8. 权利要求书骨架

### 8.1 独立权利要求骨架

按对象类型选择骨架，不要混写：

- 结构/实用新型：`基础本体 + 新增结构 + 空间位置关系 + 装配/导通/限位关系`
- 装置/系统发明：`系统架构 + 关键单元 + 不同工况下的导通/切换/响应关系`
- 方法发明：`触发条件 + 状态检测 + 判断或映射 + 输出或控制动作`

同时明确：

- 保护对象
- 必要核心部件
- 必要连接/控制关系
- 区别于现有技术的关键特征

避免把多个互不依赖的创新点都塞进权利要求 1。

### 8.2 从属权利要求骨架

可沿以下方向展开：

- 形状
- 位置
- 连接
- 通路
- 状态
- 工况
- 材料
- 参数范围
- 安装关系
- 变型实施例

## 9. 摘要骨架

保持紧凑，包含：

- 对象
- 技术领域
- 主要组成
- 关键技术路径
- 解决的问题
- 1-2 个核心效果

## 10. 待补问题

常见待补项：

- 最接近现有技术编号
- 实施例参数
- 试验数据
- 材料选择
- 连接关系
- 是否需要拆案或双轨布局
